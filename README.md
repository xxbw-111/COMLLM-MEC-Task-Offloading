# COMLLM: Multi-Turn Reasoning LLMs for MEC Task Offloading

This repository contains the training and evaluation scripts for COMLLM, a large-language-model-based task offloading framework for Mobile Edge Computing (MEC). The core idea is to serialize dynamic MEC states into natural-language prompts, warm-start the model with supervised fine-tuning (SFT), and then optimize the policy with GRPO. The full COMLLM variant adds Look-Ahead Collaborative Simulation (LACS), which estimates the future queue impact of the current offloading action.

## Method Overview

COMLLM addresses two limitations of conventional MEC offloading methods:

- DRL policies often depend on fixed-dimensional numerical states, so changing the number of edge servers may require architecture changes and retraining.
- SFT-only LLM policies tend to imitate one-step oracle labels and can become myopic under queue coupling and bursty workloads.

The pipeline is:

1. Represent each MEC state as a text instruction with units, server queue state, CPU frequency, upload rate, deadline, and recent load history.
2. Build an SFT dataset with oracle one-step decisions generated by the physical cost model.
3. Fine-tune a base model, such as Qwen 1.5B or Qwen 7B, on the SFT dataset.
4. Continue training with GRPO.
5. For COMLLM, use LACS in the reward loop: estimate immediate task cost plus the average future impact from Monte Carlo look-ahead tasks.
6. Evaluate average latency, task drop rate, performance ratio, and load balancing fairness.

## Repository Structure

| File | Purpose |
| --- | --- |
| `cost_calculator.py` | Parses MEC state strings and computes local/edge offloading latency. Also contains the LACS future-impact estimator. |
| `stf_7B.py` | SFT training entry point. |
| `grpo_new_7B.py` | GRPO training without LACS, used as the GRPO baseline. |
| `comllm_train.py` | COMLLM training with LACS-shaped reward. |
| `all_sft_model.py` | Optional utility to merge a LoRA adapter into a base model. |
| `evaluate_model.py` | Evaluates SFT/GRPO/COMLLM models on a held-out JSON test set. |
| `evaluate_random.py` | Random-policy baseline. |
| `analyze_all.py` | Aggregates evaluation result files and reports metrics. |
| `model_configs_example.json` | Example multi-model evaluation configuration. |

## Data Format

Each dataset file is a JSON or JSONL file. Each sample should contain:

- `instruction`: task instruction.
- `input`: MEC state dictionary.
- `output.action_name`: target decision string, such as `本地执行` or `卸载到边缘服务器2`.

## Reproduction Workflow

### 1. Prepare Data
```text
data/sft_train.json
data/grpo_train.json
data/comllm_train.json
data/test.json
```

The oracle label should be generated by evaluating all feasible actions under the physical cost model and selecting the action with the lowest cost.

### 2. Run SFT

```bash
python stf_7B.py \
  --base-model-name /path/to/Qwen2.5-7B \
  --dataset-path data/sft_train.json \
  --output-dir outputs/qwen2.5-7b-sft
```

The final LoRA adapter is saved to:

```text
outputs/qwen2.5-7b-sft/final_lora_adapter
```

### 3. Optionally Merge the SFT Adapter

GRPO scripts expect a model path that can be loaded as a base model. If you want a standalone SFT model directory, merge the adapter:

```bash
python all_sft_model.py \
  --base-model-path /path/to/Qwen2.5-7B \
  --lora-adapter-path outputs/qwen2.5-7b-sft/final_lora_adapter \
  --output-dir outputs/qwen2.5-7b-sft-merged
```

### 4. Train GRPO Baseline

```bash
python grpo_new_7B.py \
  --sft-model-path outputs/qwen2.5-7b-sft-merged \
  --dataset-path data/grpo_train.json \
  --output-dir outputs/qwen2.5-7b-grpo
```

### 5. Train COMLLM with LACS

```bash
python comllm_train.py \
  --sft-model-path outputs/qwen2.5-7b-sft-merged \
  --dataset-path data/grpo_train.json \
  --output-dir outputs/qwen2.5-7b-comllm \
  --lacs-weight 0.3
```

### 6. Evaluate Models

Create a config file from `model_configs_example.json`, then run:

```bash
python evaluate_model.py \
  --test-data-path data/test.json \
  --results-dir results/default \
  --model-config model_configs.json
```

Evaluate the random baseline:

```bash
python evaluate_random.py \
  --test-data-path data/test.json \
  --results-dir results/default \
  --seed 42
```

### 7. Analyze Results

Before running the analysis script, edit the configuration variables at the top of `analyze_all.py`:

```python
RESULTS_DIR = "results/default"

MODEL_NAMES = [
    "sft_model_7B",
    "grpo_model_7B",
    "comllm_model_7B",
    "random_policy",
]
```
Then run:
```bash
python analyze_all.py
```
The report includes average latency, task drop rate, performance ratio, and Jain's load balancing index.


# COMLLM：用于MEC任务卸载的多轮推理大语言模型
本仓库包含COMLLM的训练和评估脚本。COMLLM是一个基于大语言模型（LLM）的移动边缘计算（MEC）任务卸载框架。其核心思想是将动态MEC状态序列化为自然语言提示，通过监督微调（SFT）对模型进行热启动，然后使用GRPO进一步优化策略。完整版的COMLLM额外引入了前瞻协同仿真（LACS），用于估计当前卸载动作对未来队列的影响。

## 方法概述
COMLLM解决了传统MEC卸载方法的两个局限性：

- DRL策略通常依赖于固定维度的数值状态，因此当边缘服务器数量发生变化时，可能需要修改架构并重新训练。

- 仅使用SFT的LLM策略倾向于模仿单步最优标签，在队列耦合和突发流量的情况下容易变得短视。

流程如下：

1. 将每个MEC状态表示为包含单位、服务器队列状态、CPU频率、上传速率、截止期限和近期负载历史记录的文本指令。

2. 使用由物理成本模型生成的单步最优决策构建SFT数据集。

3. 在SFT数据集上微调基础模型，如Qwen 1.5B或Qwen 7B。

4. 使用GRPO继续训练。

5. 对于COMLLM，在奖励循环中使用LACS：估计即时任务成本加上来自蒙特卡洛前瞻任务的未来影响平均值。

6. 执行推理，输出卸载策略

## 复现流程
### 1. 准备数据
准备数据集：
```bash
data/sft_train.json
data/grpo_train.json
data/comllm_train.json
data/test.json
```
最优标签应通过在所有可行动作上评估物理成本模型，并选择成本最低的动作来生成。

### 2. SFT训练
```bash
python stf_7B.py \
  --base-model-name /path/to/Qwen2.5-7B \
  --dataset-path data/sft_train.json \
  --output-dir outputs/qwen2.5-7b-sft
```

最终LoRA适配器保存在：
outputs/qwen2.5-7b-sft/final_lora_adapter

GRPO脚本期望一个可作为基础模型加载的模型路径。如果您想要一个独立的SFT模型目录，请合并适配器：
```bash
python all_sft_model.py \
  --base-model-path /path/to/Qwen2.5-7B \
  --lora-adapter-path outputs/qwen2.5-7b-sft/final_lora_adapter \
```

### 4. 训练GRPO基线
```bash
python grpo_new_7B.py \
  --sft-model-path outputs/qwen2.5-7b-sft-merged \
  --dataset-path data/grpo_train.json \
  --output-dir outputs/qwen2.5-7b-grpo
```

### 5. 训练带LACS的COMLLM
```bash
python comllm_train.py \
  --sft-model-path outputs/qwen2.5-7b-sft-merged \

  --output-dir outputs/qwen2.5-7b-comllm \

```

### 6. 评估模型

```bash
python evaluate_model.py \
  --test-data-path data/test.json \
  --results-dir results/default \
  --model-config model_configs.json
```

```bash

  --test-data-path data/test.json \
  --results-dir results/default \
```

### 7. 分析结果
运行分析脚本前，请先修改 `analyze_all.py` 文件开头的配置变量：

```python
RESULTS_DIR = "results/default"
```

```bash
python analyze_all.py
```
